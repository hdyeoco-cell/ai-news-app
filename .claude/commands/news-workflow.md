# 뉴스 수집기 기능 개발 워크플로

뉴스 수집기 앱에서 새 기능을 개발할 때 사용하는 명령이다.
브랜치 이름: $ARGUMENTS

아래 단계를 **순서대로** 실행한다.

## 1. 현재 상태 확인
- `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인한다.
- 현재 브랜치가 `main`이 아니면 경고를 주고, **main으로 이동할지 사용자에게 물어본다.** 답을 받기 전에는 이동하지 않는다. 사용자가 거절하면 중단한다.
- 커밋되지 않은 변경이 있으면 알려 주고 어떻게 할지 물어본다.

## 2. 브랜치 생성
- `$ARGUMENTS`가 있으면 그 이름으로 `git checkout -b <이름>`을 실행한다.
- `$ARGUMENTS`가 비어 있으면 어떤 기능을 개발할 것인지 물어본다. 답을 들으면 **영어 소문자-하이픈 형식**(예: `add-category-filter`)으로 브랜치 이름을 제안하고, 사용자가 확인하면 생성한다.

## 3. 시작 안내
- 브랜치 생성이 끝나면 **"이제 개발을 시작하세요!"** 라고 안내한다.
- 프로젝트 `CLAUDE.md`를 다시 읽고 기술 스택과 컨벤션을 요약해서 알려 준다.
  - 스택, 주요 명령어(`npm run build`, `npx tsc --noEmit`, `npm run lint`), 비용 통제 한도, Next.js 16 주의사항, UI 변경 시 `ui.md` 참고, 실패 격리 원칙 등 이번 작업과 관련 있는 항목 위주로 정리한다.

## 4. 완료 처리
사용자가 **"완료"** 또는 **"done"** 이라고 입력하면:
1. `git status`와 `git diff --stat`으로 변경된 파일 목록을 보여 준다.
2. 변경 내용에 맞는 커밋 메시지를 자동으로 제안한다. 이 저장소의 기존 커밋 스타일(`git log`, 한국어 한 줄 요약)을 따른다.
3. 사용자가 확인하면 커밋한다. (수정을 원하면 반영한다.)
4. `main`으로 이동해 작업 브랜치를 병합한다 (`git checkout main` → `git merge <브랜치>`). 충돌이 나면 중단하고 사용자에게 알린다.

## 5. 요약
- 병합이 끝나면 이번 작업 내용을 요약해서 보여 준다: 브랜치 이름, 변경된 파일, 커밋 메시지, 병합 결과.
